## 1. Executive Summary

This survey provides a comprehensive architectural analysis of SlipEngine's asset management, serialization mechanics, build environment, and automated test harness to guide the design and implementation of the upcoming node-based Material Editor (Shader Graph).

### Key Takeaways:
1. **Asset Pipeline & GUID System**: SlipEngine uses an explicit companion `.meta` file system (similar to Unity). Every asset has a GUID generated by `SlipModelExtract::GenerateUID()` (UUIDv4 128-bit hex string) and is registered/located via `SlipFileSystem::GetGuidForAsset` and `SlipFileSystem::FindAssetByGuid`.
2. **Serialization Format**: Engine files (`.mat`, `.scene`, `.prefab`, `.controller`) utilize custom, human-readable, indented/key-value text formats parsed with `std::stringstream` and standard C++ string manipulation. Additionally, `rapidjson` (header-only, version 2025-02-26) and `pugixml` are already installed and available in `build/vcpkg_installed/x64-windows/include` via vcpkg dependencies.
3. **Build System**: Standard CMake 3.22+ configuration using Visual Studio 2022 (`v143` MSVC compiler `cl.exe 14.44.35207`, x64) and vcpkg in manifest mode (`vcpkg.json`). Targets include dynamic library `SlipEngine`, desktop runner `SlipRunner`, editor `SlipEditorApp`, and three test executables (`SlipTestLua`, `SlipTestRenderOpt`, `SlipTestTerrain`).
4. **Automated Testing Setup**: Unit and integration test suites are standalone console executables that execute assertions (`assert(...)`), print structured `[PASS]` tags, and return exit code `0` on success. Crucially, `tests/test_terrain.cpp` demonstrates headless hidden OpenGL context creation via SDL2 and GLAD, enabling real GPU shader compilation tests in headless automated environments without opening visible windows.
5. **UI & Canvas Paradigm**: `AnimatorGraphPanel` provides a production-tested blueprint for ImGui node graph canvases, featuring grid background rendering, right/middle click panning, mouse wheel zooming, draggable nodes, and interactive wire linking.

## 2. Asset Pipeline Architecture

### 2.1 Asset Identification and File Formats
SlipEngine associates asset types by file extension, centralized in `SlipModelExtract::DeduceAssetType` (`src/editor/SlipModelExtract.cpp:57-84`):
- **Materials**: `.mat` — custom key-value text format (`src/render/SlipMaterial.cpp`).
- **Scenes / Levels**: `.scene`, `.level` — indented entity hierarchy text format (`src/scene/SlipLevel.cpp`).
- **Prefabs**: `.prefab` — indented entity hierarchy text format (`src/scene/SlipPrefab.cpp`).
- **Animation Controllers**: `.controller` — indented state machine graph format (`src/render/SlipAnimatorController.cpp`).
- **Animation Clips**: `.clip`, `.anim` — binary or keyframe format (`SlipAnimation.cpp`).
- **Shaders**: `.vert`, `.frag`, `.glsl` — GLSL shader files (`assets/shaders/`).
- **Models**: `.fbx`, `.obj`, `.dae`, `.gltf`, `.glb`, `.smd`.
- **Textures**: `.png`, `.jpg`, `.jpeg`, `.tga`, `.bmp`, `.hdr`.

### 2.2 Companion `.meta` Files & GUID System
Asset references are decoupled from fragile relative file paths using persistent GUIDs.
- **GUID Generation**: In `src/editor/SlipModelExtract.cpp:38-55`, `SlipModelExtract::GenerateUID()` generates 36-character standard UUID strings:
  ```cpp
  // Format: 8-4-4-4-12 hex characters
  // e.g. 7f8a9b2c-3d4e-5f60-8a1b-c2d3e4f5a6b7
  ```
- **Metadata Storage**: For an asset at `<asset_path>`, a companion file `<asset_path>.meta` is created:
  ```yaml
  guid: 8fa234b1-912c-4933-9f44-1289ae5c0321
  type: ShaderGraph
  originalFile: ProceduralWater.shadergraph
  fileSize: 4210
  ```
- **GUID Resolution API**:
  - `SlipFileSystem::GetGuidForAsset(path)`: Reads `<path>.meta` and extracts the `guid:` field.
  - `SlipFileSystem::FindAssetByGuid(guid)`: Recursively scans `assets/` for `.meta` files to locate the corresponding asset path.
  - `SlipModelExtract::EnsureMetaForFile(path, outMeta)`: Automatically verifies or generates the `.meta` companion file if absent.

### 2.3 Path Conventions and Storage Directories
SlipEngine organizes assets under the project root (`c:\Projects\SlipEngine\` or project-specific directory configured via `SlipProject`):
- `SlipFileSystem::GetProjectAssetsPath()` -> resolves to `<ProjectRoot>/assets/`.
- Standard folders:
  - `assets/materials/` — saved `.mat` material files.
  - `assets/shaders/` — saved `.vert`, `.frag`, and custom shaders.
  - `assets/scenes/` — `.scene` files (e.g. `Main.scene`).
  - Recommended for Shader Graphs: `assets/shaders/` or `assets/materials/` (e.g. `assets/materials/MyShader.shadergraph`).

## 3. Serialization Systems & Vendor Libraries

### 3.1 Existing Serialization Paradigms

SlipEngine uses a uniform, human-readable, line-oriented text format across all asset types:
1. **Key-Value Text Format (`.mat`)**:
   - Written by `SlipMaterial::Save(const std::string& path)` (`src/render/SlipMaterial.cpp:224-260`).
   - Parsed line-by-line via `std::getline` and `line.find(':')`.
   - Sample content:
     ```yaml
     shader: Lit
     color: 1 1 1
     roughness: 0.5
     metallic: 0
     ao: 1
     diffuseTexture: assets/textures/wood.png
     normalTexture: assets/textures/wood_norm.png
     ```
2. **Indented Hierarchical Text Format (`.controller`, `.prefab`, `.scene`)**:
   - Used by `SlipAnimatorController::SaveToFile` / `LoadFromFile` (`src/render/SlipAnimatorController.cpp:404-536`).
   - Uses 2-space indentation to define blocks (`States:`, `State:`, `Transition:`, `Condition:`).
   - Contains node canvas coordinates:
     ```yaml
     AnimatorController:
       Name: PlayerController
       DefaultState: Idle
       Parameters:
         Parameter: Speed float 0.00
       States:
         State:
           Name: Idle
           Clip: idle.anim
           Speed: 1.0
           Position: 250.0 200.0
           Transition: Walk 0.25 0 0.9
             Condition: Speed 0 0.1 0
     ```

### 3.2 Third-Party Serialization Libraries Available

Inspection of `build/vcpkg_installed/x64-windows/include` reveals:
- **`rapidjson`**: Fully installed and available under `rapidjson/` (`document.h`, `writer.h`, `prettywriter.h`, `stringbuffer.h`, `reader.h`).
- **`pugixml`**: Fully installed and available (`pugixml.hpp`).
- **nlohmann/json / yaml-cpp**: Not installed in vcpkg manifest.

### 3.3 Recommendation for Shader Graph Serialization
Two viable architectural paths exist:
1. **Option A: Indented Line-Oriented Text (`.shadergraph`)**:
   - Matches the exact design of `SlipAnimatorController`, `.prefab`, and `.mat`.
   - Zero external dependency quirks, trivial line-by-line parsing, human-readable, easy git merging.
2. **Option B: JSON via `rapidjson` (`.shadergraph`)**:
   - Standard node graph format (similar to Blender / Unreal Material Graph JSON).
   - Schema naturally represents tree and list structures with typed inputs/outputs.
3. **Recommendation**: Implement a dedicated `SlipShaderGraphSerializer` supporting a clean, indented text format (or JSON via rapidjson). Given the project's consistent use of indented text in `SlipAnimatorController` and `SlipPrefab`, an indented text format or straightforward JSON is completely native to the codebase.

### 5.2 Headless OpenGL Context Creation Pattern
A critical architectural pattern for testing shader compilation and OpenGL shader programs is established in `tests/test_terrain.cpp:19-37`:
```cpp
// Initialize hidden SDL2 OpenGL context for headless testing
SDL_Init(SDL_INIT_VIDEO);
SDL_GL_SetAttribute(SDL_GL_CONTEXT_MAJOR_VERSION, 3);
SDL_GL_SetAttribute(SDL_GL_CONTEXT_MINOR_VERSION, 3);
SDL_GL_SetAttribute(SDL_GL_CONTEXT_PROFILE_MASK, SDL_GL_CONTEXT_PROFILE_CORE);
SDL_Window* window = SDL_CreateWindow("TestContext", 0, 0, 128, 128, SDL_WINDOW_OPENGL | SDL_WINDOW_HIDDEN);
SDL_GLContext glContext = SDL_GL_CreateContext(window);
gladLoadGLLoader((GLADloadproc)SDL_GL_GetProcAddress);
```
This pattern allows the test suite to:
- Compile real GLSL vertex and fragment shaders generated by the Shader Graph.
- Link shader programs into real OpenGL programs (`glCreateProgram`, `glLinkProgram`).
- Verify uniform locations (`glGetUniformLocation`).
- Test all shader variants headlessly in automated environments with 100% deterministic results.

  - To support Shader Graph:
    1. Add `std::string shaderGraphPath` to `SlipMaterial` (and serialize in `.mat` as `shaderGraph: <path>`).

## 7. Architectural Recommendations for Implementation

### 7.1 New Build Target in CMakeLists.txt
Add `SlipTestShaderGraph` to `CMakeLists.txt`:
```cmake
# 7. Suite de Pruebas de Shader Graph y Generacion GLSL
add_executable(SlipTestShaderGraph 
    "${CMAKE_CURRENT_SOURCE_DIR}/tests/test_shader_graph.cpp"
)
target_compile_definitions(SlipTestShaderGraph PRIVATE SLIP_USE_DLL)
target_include_directories(SlipTestShaderGraph PRIVATE ${SLIP_INCLUDE_DIRS})
target_link_libraries(SlipTestShaderGraph PRIVATE 
    SlipEngine 
    SDL2::SDL2 
    SDL2::SDL2main
    glad::glad
)
```

### 7.2 Core Classes Recommended for Shader Graph Architecture
1. **Data Model (`SlipShaderGraph`)**:
   - `enum class ShaderGraphMaterialType { Lit, Unlit };`
   - `struct ShaderGraphPin { int id; std::string name; PinType type; PinKind kind; /* input or output */ };`
   - `struct ShaderGraphNode { int id; std::string type; std::string title; ImVec2 position; std::vector<ShaderGraphPin> inputs; std::vector<ShaderGraphPin> outputs; /* properties */ };`
   - `struct ShaderGraphLink { int id; int startPinId; int endPinId; };`
   - `struct ShaderGraphProperty { std::string name; PropertyType type; ... };`
2. **GLSL Code Generator (`SlipShaderGraphCompiler`)**:
   - Performs topological sort on nodes connecting to the Master Node.
   - Generates GLSL vertex shader (standard PBR transforms, UVs, world pos, normals, or custom vertex offsets).
   - Generates GLSL fragment shader (math evaluation chain leading to master PBR Lit or Unlit outputs).
   - Injects engine uniforms (`u_Time`, `u_DeltaTime`, `u_CameraPos`, `u_Model`, `u_View`, `u_Projection`, lighting uniforms).
3. **Serialization (`SlipShaderGraphSerializer`)**:
   - Saves/loads `.shadergraph` files cleanly using indented text matching engine conventions.
4. **Editor UI Panel (`ShaderGraphPanel`)**:
   - Derives from `EditorPanel`.
   - Leverages the canvas rendering patterns established in `AnimatorGraphPanel`.
   - Exposes public property list sidebar, node palette popup (right click), interactive link dragging, and live preview / compile status.
5. **Material Integration (`SlipMaterial` & `InspectorPanel`)**:
   - Allow materials to specify a Shader Graph.
   - Automatically display exposed shader graph properties in `RenderSlipMaterialPropertiesEditor` when a graph is bound.
